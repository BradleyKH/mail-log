# Content

Everything the site shows comes from this folder. The site imports it through the `@content` alias in `site/src/content/load.ts`; the schemas are in `site/src/content/schema.ts`. Run `pnpm --filter site validate` after any change.

`fixtures/` holds small content trees for the validator's tests. The site never loads them.

## Reports: `docs/<docId>/`

Only `cr-159065`, `cr-159063`, `cr-159064`, `cr-159066`, `cr-177948`, `cr-177949`, and `cr-177950` may exist here; any other folder fails validation and the build.

| File | Shape |
|---|---|
| `doc.json` | `{ docId, reportNumber, title, date: "1979-05" or "1985-07", ntrsId, pdfPath, stem, pageCount }` |
| `pages/page-NNN.md` | One file per PDF page, generated by script; never edit by hand. |
| `overrides/page-NNN.md` | Corrected or transcribed pages in the same format, with `source: reviewed` or `source: ai`; `source: ocr` is rejected. The import script copies an override in place of the generated page; the site never reads this folder directly. |
| `sections.json` | `{ id, title, level, pdfPage }[]` |
| `figures.json` | `{ number, title, pdfPage, sectionId }[]` (`number` is the printed figure id as a string, such as `"27"`, `"5.4.1-17"`, or `"6.3.2"`; `sectionId` may be `null`) |
| `glossary.json` | `{ term, definition, pdfPage }[]` |
| `flowcharts.json` | `cr-159063` only, generated: `{ routine, figure, caption, pdfPages }[]` (`figure` is the printed figure id as a string) |

### Page files

YAML frontmatter, then a Markdown body.

```yaml
pdfPage: 87            # values here are illustrative
folio: "75"            # printed page number as a quoted string, or null
sectionId: B.AUSEA     # or null
kind: listing          # text | figure | mixed | blank | cover | flowchart | listing
source: ocr            # ocr | reviewed | ai
confidence: 81.4       # 0 to 100
figures: []            # printed figure ids (strings, e.g. ["5.4.1-17"]) shown on this page
listing:               # listing pages only
  appendix: B
  routines: [AUSEA]    # in the order they appear on the page
  listingPage: 71      # compiler page number, or null
```

Body conventions: terminal and line-printer output in fenced `text` blocks; a listing page is one fenced `fortran` block with one printed line per line as `(NNNN) <code>`, fixed-form columns preserved (compiler symbol-table and cross-reference pages that follow a routine are `kind: listing` with a fenced `text` block and no `(NNNN)` lines); `[illegible]` where the scan cannot be read; flowchart pages hold only the caption.

Listing sequence numbers run continuously through an appendix, and lines pulled in by `$INSERT` all print the insert statement's number, so equal numbers repeat. The same routine name can appear in more than one appendix, so a routine is identified by its appendix and name. Within a routine sequence numbers never decrease from page to page (gaps warn, decreases error); a drop in sequence number on a page that lists several routines marks the start of the next routine.

### The 1985 volumes

`cr-177948`, `cr-177949`, and `cr-177950` (July 1985, 273, 173, and 241 pages) have `doc.json`, `sections.json`, `figures.json`, and `pages/`. Their pages are generated from the Tesseract OCR like the 1979 reports, with the same frontmatter. `cr-177948/overrides/` holds two reviewed pages that correct OCR folios (pages 12 and 222), and `cr-177950` has no `overrides/` folder. Neither has a `glossary.json` because the manuals have no glossary, and the known-gaps list records that. `cr-177949` also has `glossary.json`.

`cr-177949/overrides/` holds two reviewed pages that correct OCR section headings (pages 69 and 78) and 39 AI transcriptions of the Vol. II appendix printouts (PDF pages 119 to 132, the even pages 134 to 160 and 161 to 170, and 172). Each transcription has `source: ai`, a `confidence` of 100 (38 pages) or 99 (`page-150`), the page's `folio` and `sectionId`, and a fenced `text` block that reproduces the printout. The printouts' own totals are checked in the transcription's `checks` list, and the transcription is kept as printed where a check fails. The `.ai/` folder under `sources/` holds the transcriptions' own frontmatter, which carries those checks; the site and the validator read only these overrides.

The page transcriptions of these three volumes reproduce printed names, so the name denylist exempts their `pages/` and `overrides/` folders; the Validation section of the root [`README.md`](../README.md) describes the check.

## The program: `program/`

Records are `correspondence`, `dir`, and `drawing-eo`. Page numbers refer to `cr-159065`.

| File | Shape |
|---|---|
| `flows/<record>.json` | `{ record, title, entryStep, steps: Step[] }` |
| `fields/<record>.json` | `{ name, label, length?, searchable, description, pdfPage }[]` |
| `records/<record>.json` | Sample records from the output figures: objects keyed by field name, each with a `sourceFigure` figure id string. |

`Step` is `{ n, mode, title?, prompt, input?, response?, branches, next?, figures, pdfPage }`, where `figures` is an array of figure id strings, `mode` is `input | revise | search | archive | menu | common`, `prompt` is the printed prompt lines, `input` is `{ pattern, description, maxLength? }`, and each branch is `{ when, goto }`. `goto` and `next` are a step number in the same flow or `"exit"`.

## The code: `code/`

| File | Shape |
|---|---|
| `descriptions.json` | `{ routine, record, sectionId, description, pdfPage }[]` from `cr-159063` sections 4.0, 8.0, and 9.0. `record` is a record type or `general`, `external`, or `support`; `sectionId` refers to `cr-159063`. |
| `index.json` | Generated by `pnpm --filter site code-index`: `{ totals, externals, unresolvedCalls, routines }` (shape below). |
| `xref.json` | Generated: links between flow steps and routines (shape below). |
| `routines/<id>.f` | Generated: one routine's listing lines as printed, one card per line, column 1 first. |
| `routines/<id>.lines.json` | Generated: `{ routine, lineIds, pages: { pdfPage, firstLine, lastLine }[] }`; `lineIds[i]` is the id of line `i + 1` of the `.f` file. |

The code index is built from the `cr-159064` listing pages. Routine boundaries come from the code itself (`SUBROUTINE`/`FUNCTION` headers and `END`), with page frontmatter used only as a hint. A routine id is its name when the name is unique, `NAME@<appendix>` when the name recurs across appendices (`TINPUT@C`), and `NAME@F-<program>` for the `OPEN` and `CLOSE` each Appendix F program carries (`OPEN@F-PHASE1`). A headerless main program is named for the section it starts in (`MAIN`, `PHASE1`). A line id is the printed sequence number plus a 1-based ordinal among the routine's lines with that number (`0795.2`, since `$INSERT` repeats numbers), or `uN` in Appendices E and F, which print none.

`index.json`:

- `totals`: `{ routines, lines, commentLines, byAppendix: { B..F: { routines, lines, commentLines } } }`.
- `externals`: `{ name, group: "system" | "miscellaneous", sectionId, pdfPage }[]`, the routines `cr-159063` section 8.0 lists as outside the program.
- `unresolvedCalls`: `{ routine, name, lines }[]`, CALL targets that are neither a routine nor an external.
- `routines`: `{ id, name, appendix, record, kind, sectionId, lines, commentLines, firstSeq, lastSeq, listingPages, symbolTablePages, flowchartFigure, flowchartPages, description, descriptionPage, calls, calledBy, commons, files, prompts, reviewed }[]` in listing order. `record` is a record type or `general`, `external`, or `support`; `kind` is `main | subroutine | function | program`; `sectionId` refers to `cr-159064`; `flowchartPages` and `descriptionPage` refer to `cr-159063`; `calls` is `{ name, target, kind: "routine" | "external" | "unresolved", lines }[]` with `target` a routine id or `null`; `files` is `{ unit, kind: "unit" | "file", mode, purpose }[]` (`mode` joins `read`, `write`, `rewind`, `endfile`, `open`, `close` with `/`; `purpose` is the comment just above a use, or `null`); `prompts` is `{ line, text }[]`, the literal text of WRITE and FORMAT statements, one entry per printed line; `reviewed` is true when any of its listing pages is a reviewed override.

`xref.json`: `{ threshold, stepToRoutines, routineToSteps, unmatchedSteps, unmatchedRoutines }`. `stepToRoutines` is `{ record, step, matches: { routine, score, line, promptLine }[] }[]`, best first, where `line` is the routine's prompt line id and `promptLine` indexes the step's `prompt`; matching is fuzzy (character trigrams weighted against boilerplate, input masks such as `XXX` removed) and keeps scores at or above `threshold`. `routineToSteps` is `{ routine, steps: { record, step, score }[] }[]`. `unmatchedSteps` lists steps with matchable prompt text but no match; `unmatchedRoutines` lists routine ids no step matched.

## SPADS: `spads/`

Data from the 1985 volumes, loaded through the `spads*` loaders in `site/src/content/load.ts`. Each file is optional; the validator parses every file that exists against its schema, and objects are strict, so an unknown key fails. Page numbers refer to `cr-177949` unless a field says otherwise.

| File | Shape |
|---|---|
| `fields.json` | `{ n, name, label, description, pdfPage, partial? }[]`: the 26 header fields of the Contract Analysis record (PDF 21 to 22). |
| `jobOrderFields.json` | Same shape: 12 job-order field definitions (PDF 34). |
| `records.json` | `SpadsRecord[]`: 30 sample records keyed by `sysnum`, each with the header values, `jobOrders` (`{ jo, sub, progno, all, fy }`, where `fy` holds up to eight fiscal-year percents), `months` (`{ month, cmaa, eacHours, eacDollars, actHours, actDollars, compHours, compDollars }`, with `month` as printed, such as `JUL85`), and `sourcePages`. `status` is `AUT`, `FUT`, or empty, and `table` is `SUST`, `MANL`, or empty, where a printout does not give them. |
| `tables.json` | `{ fee, rates, sustaining, programNumbers, time }`. `fee` is `{ contract, task, subtask, fee, masked?, pdfPage }[]`, where `fee` is null for a masked printout value and `masked` keeps the printed text (such as `**.000`). `rates` is `{ task, fy, hourRate, dollarRate, illustrative }[]`; every rate is marked illustrative. `sustaining` maps each fiscal year to its percent, `programNumbers` is `{ jo, progno }[]`, and `time` is `{ task, start, end, contractValue, baseFee }[]`. |
| `reports.json` | `{ id, title, pdfPages, options, printout, verified }[]`: 31 sample reports from the appendices. `verified` is `{ what, result }[]`, the arithmetic checks run against the printout; each `result` begins with `pass`, `fail`, or `n/a`. |
| `menus.json` | `Record<string, string | string[]>`: menu screens keyed by name (`spadsMain`, `analysisMain`, `spoolMain`, `reportMain`, `updateMain`, and the rest), each a line of text or a list of lines. |

The validator checks these shapes only. It does not cross-check `records.json` against `fields.json` or `reports.json` against the figures.

## Known gaps: `reports/known-gaps.json`

Optional. `{ file, messagePrefix, reason }[]`: a validator warning whose file path equals `file` (relative to this folder) and whose message starts with `messagePrefix` is reported as a known gap and does not fail `pnpm --filter site validate -- --strict`. Errors are never suppressed. When the file is absent, nothing is allowlisted. The validator's `--known-gaps <path>` flag reads the list from another location.
